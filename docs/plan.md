# 구현 Plan

기준: [spec.md](spec.md). 시간은 제안값이다. 단계마다 완료 기준을 확인한 뒤 커밋한다.

| # | 단계 | 산출물 | 완료 기준 | 시간 |
|---|---|---|---|---|
| 0 | 인프라 골격 | `compose.yaml`, DB 초기화 SQL, PgBouncer ini, SeaweedFS 초기 설정 | `docker compose up`으로 전부 뜸. pg-src 쓰기가 pg-dst에 복제됨. s3-src 무인증 GET 거부, s3-dst 허용 | 50분 |
| 1 | 앱·writer | `app/`, `writer/` | writer 실행 중 행이 늘고, 같은 멱등 키 재전송이 중복 저장되지 않음 | 30분 |
| 2 | 플랫폼 뼈대 | 상태 머신, 이벤트 버스, SSE, Idempotency-Key, 콘솔 골격 | 정의된 전이만 통과하고 그 외는 거부됨. 콘솔에 상태와 이벤트가 실시간으로 보임 | 40분 |
| 3 | S1 | COLLECT, ANALYZE(정적 탐지), 기본 이전안, 게이트 G1~G3 | 게이트 1차가 G1에서 BLOCK, 같은 입력 반복 시 같은 판정 | 40분 |
| 4 | S2 | 제안서 스키마, 린트, 도구 계층, Claude 호출(live/replay), 리허설 버킷 검증, 결속 승인 | 실제 호출로 제안서 생성 → 리허설 통과 → 재대조 PASS → 승인. 잘못된 제안서와 파괴적 명령은 거부·기록 | 50분 |
| 5 | S3 | Executor 8단계, 영수증, writer 대조 | writer를 돌린 상태에서 컷오버 성공. 영수증 MATCH, 유실·중복 0, 쓰기 정지 ms 표시 | 50분 |
| 6 | S4 | 장애 주입, 되돌리기 | 컷오버 뒤 목적지에 쓴 행이 되돌리기 후 출발지에 모두 있음, failback 영수증 MATCH | 30분 |
| 7 | 시연 정리 | 콘솔 다듬기, reset 스크립트, README 실행법, 30초 시연 순서 | reset 후 S1~S4를 처음부터 다시 실행해 같은 결과 | 20분 |

합계 약 5시간 10분.

## 시간이 모자랄 때 줄이는 순서

1. 6단계: 되돌리기를 진행 표시만 하는 모의로 바꾼다.
2. 5단계: writer 대조를 빼고 영수증만 남긴다.
3. 4단계: 실제 호출을 빼고 replay만 쓴다.

0·3·5단계의 실제 DB·게이트·영수증은 끝까지 남긴다.

## 미리 확인할 위험

- SeaweedFS 무인증 접근 제어 방식(0단계): 버킷 단위 공개·차단이 안 되면 G1 시험 방법을 바꿔야 한다.
- PgBouncer `RELOAD`로 대상 DB가 바뀌는지(5단계): 안 되면 PAUSE 중 컨테이너 재시작으로 대체하고, 쓰기 정지 시간에 그 시간을 포함한다.
- 역방향 구독 생성 시점(5단계): 6단계를 PAUSE 안에서 해야 그 사이 쓰기가 빠지지 않는다.
